## Why

Кожен дані-екран (`front/src/views/`: `ProjectsView`, `TimeCampView`,
`JiraView`, `TempoView`, `JournalView`, `UsersView`) **копіпастить** один і той
самий каркас: `<div class="page">` → `PageHeader` (title + опц. desc + слот
`#actions` у верхньому правому куті) → опційний суб-бар (Tabs / `.pipe` /
`.cal__chips`) → банер помилки `<p class="data-error">` → `<div
class="page__body">`. Наявний `PageHeader.vue` покриває лише **верхівку**
(title+desc+actions), а `.page`-обгортку, банер помилки і `.page__body` кожна
в'юха збирає руками. Це породжує дублювання і дрейф (різний рендер помилки,
різні відступи), а попереду — **багато нових таблиць**, де цей каркас
повторюватиметься знову і знову.

## What Changes

- **Frontend (новий компонент):** додаємо **єдиний переюзовний каркас сторінки**
  `components/data/DataPage.vue`, що інкапсулює: `.page` wrapper; **заголовок**
  (`title` обов'язковий, `desc` опційний); **кнопки у верхньому правому куті**
  через слот `#actions`; **закладки (окремі під-сторінки)** через опційний prop
  `tabs` + `activeTab` (+ подія зміни) — рендеряться смугою під заголовком, а
  тіло показує активну закладку; опційний слот `#toolbar` (суб-бар під
  заголовком/закладками — для фільтрів/`pipe`/chips); авто **банер помилки**
  через prop `error?: string | null`; **дефолтний слот = тіло** сторінки
  (рендериться в `.page__body`).
- **Frontend (рефактор, без зміни поведінки):** переводимо наявні дані-екрани
  (`ProjectsView`, `TimeCampView`, `JiraView`, `TempoView`, `JournalView`,
  `UsersView`) на `DataPage` — суто заміна повторюваної розмітки на компонент.
  `PageHeader` стає **внутрішньою деталлю** `DataPage` (поглинається).
- **Поза скоупом:** `CalendarView` (власний `.cal`-layout, не `.page`); бекенд,
  схема БД, контракти API — не зачіпаються; жодної зміни поведінки екранів.

## Capabilities

### New Capabilities

- `frontend-page-shell`: переюзовний каркас сторінки (`DataPage`) — заголовок +
  дії у верхньому правому куті + **закладки (окремі під-сторінки)** + опційний
  тулбар + банер помилки + тіло; основа для всіх майбутніх дані-/табличних
  екранів.

## Impact

- **Frontend:** новий `components/data/DataPage.vue`; рефактор 6 в'юх на нього;
  `PageHeader.vue` поглинається в `DataPage` (або лишається його приватним
  під-компонентом). Стилі — наявні в `styles/shell.css` (`.page*`), нових майже
  не треба. i18n — наявні ключі заголовків, нових рядків не треба.
- **Без бекенду / міграцій / змін контрактів API.** Ризик низький — рефактор
  розмітки; перевірка `npm run build` (`vue-tsc` + `vite`) має бути чистою, а
  поведінка кожного екрана — без змін.
