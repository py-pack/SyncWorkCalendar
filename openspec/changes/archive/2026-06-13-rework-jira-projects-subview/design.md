## Context

Під-вʼюха «Проекти → Jira» (`JrProjects.vue`) лишилася на патерні до
`rework-projects-screen`: плоский `DataTable` з колонками `key`/`name`/
`issues_count` і **інлайн-тоглом `is_watched`**. TimeCamp-під-вʼюху вже
переробили (фільтр за `is_sync`, пошук, попап, тьмяні архівні). Переносимо ті
самі рішення на Jira.

Звірені факти коду:
- Модель `JRProject` — **плоска**: `key`, `name`, `is_archved` (одрук збережено,
  D-008), `is_watched`. **Немає `color`, немає `parent_id`** → ні дерева, ні
  кольору.
- `GET /jr-projects` → `JRProjectWithCount` (`id`/`key`/`name`/`is_archived`/
  `is_watched`/`issues_count`). `issues_count` рахується subquery-єм **без
  періоду** → це кількість **усіх** задач проекту. Міняти не треба.
- `PATCH /jr-projects/{id}` приймає лише `is_watched` (локальний прапор; у Jira
  нічого не пишемо).
- `JrProjects.vue` уже вантажить себе сама (`store.loadJrProjects()`,
  ідемпотентно, D10 TimeCamp-зміни) — цей механізм лишається.
- У сторі `toggleJrWatched(p)` робить `PATCH {is_watched: !p.is_watched}` +
  локальне оновлення.

## Goals / Non-Goals

**Goals:**
- Дзеркало TimeCamp-UX на Jira: фільтр за станом синку (`is_watched`), швидкий
  локальний пошук, попап редагування замість інлайн-тогла, тьмяні архівні.
- Нульова зміна бекенду — усе клієнтське поверх наявних endpoint-ів.

**Non-Goals:**
- Без дерева/кольору/тега задачі (Jira-проекти плоскі, без `color`, без маппінгу).
- Без бекенду, міграцій, контрактів API.
- Без серверного фільтра/пошуку — усе по завантаженому списку на клієнті.
- TimeCamp-під-вʼюха не зачіпається.

## Decisions

### D1 — Фільтр за станом синку (`is_watched`), клієнтський

Під-вʼюха Jira отримує фільтр `усі | у синку | не в синку`, що фільтрує
**завантажений** список за `is_watched` на клієнті (без re-fetch): `у синку` →
`is_watched = true`; `не в синку` → `is_watched = false`; `усі` → без фільтра.
Стан фільтра — `jrActive` у сторі (як `tcActive`). Архівні проекти від фільтра
не залежать (завжди показані, лише тьмяні).

- **Чому `is_watched` = «синк»:** для Jira «синхронізуватися» означає
  «відстежувати» проект (`is_watched`); це прямий аналог `is_sync` у TimeCamp.
- **Чому клієнтський:** `is_watched` уже в кожному рядку; фільтр миттєвий, 0
  запитів — узгоджено з TimeCamp-рішенням (D4 `rework-projects-screen`).

### D2 — Швидкий пошук по локальних даних (`key`/`name`)

Поле пошуку фільтрує вже завантажені проекти case-insensitive по `key` **або**
`name`, на клієнті, без запиту на сервер; комбінується з фільтром стану синку.
Дзеркало TimeCamp-пошуку (там по `name`/`issue_key`/`issue_name`; у Jira полів
менше).

### D3 — Попап замість інлайн-тогла; **простіший** за TimeCamp

Інлайн-`Toggle` `is_watched` прибирається (ризик випадкового кліку). Налаштування
синку — у модалці, що відкривається кнопкою-шестернею **або подвійним кліком** по
рядку. **На відміну від TimeCamp**, попап Jira містить **лише тогл «увімкнути/
вимкнути синхронізацію»** (`is_watched`):
- **немає** select-а задачі (Jira-проект не мапиться на одну задачу);
- **немає** правила «Save заблоковано» — **Save завжди дозволено** (єдине поле —
  булевий тогл).
Save → `PATCH /jr-projects/{id} {is_watched}` + локальне оновлення рядка (як
`saveTcSync`). У сторі `toggleJrWatched` замінюємо на `saveJrWatched(id,
is_watched)`.

- **Реалізація модалки:** нова `components/projects/JrSyncSettingsModal.vue` на
  тому самому `Sheet`-патерні, що TimeCamp `SyncSettingsModal`, але з одним
  тоглом. Окремий компонент (а не переюз TimeCamp-модалки) — бо вміст інший і
  спрощений; дублювання мінімальне.

### D4 — Рядок: індикатор стану синку + лічильник + шестерня; тьмяні архівні

Замість тогла рядок показує: `key`, `name`, `issues_count` (усі задачі),
**індикатор стану синку** («відстежується / ні» за `is_watched`, той самий
стиль, що TimeCamp `sync_state_on/off`) і кнопку-шестерню. Архівні проекти
(`is_archived`) — сірі/напівпрозорі. `issues_count` лишається видимим для всіх
проектів.

- **Рендер:** лишаємо `DataTable` (Jira-проекти плоскі — дерево не потрібне);
  колонку-тогл замінюємо на стан синку + шестерню. Альтернатива — кастомний
  список як у TimeCamp-дереві — відкинуто (зайве для плоского списку).

### D5 — i18n: переюз наявних ключів

Фільтр — наявні `flt_all`/`flt_active`/`flt_inactive` («Усі / У синку / Не в
синку»); стан синку — `sync_state_on`/`sync_state_off`; пошук — `search`. Для
попапу: заголовок/тогл — переюз `ssm_title`/`ssm_enable` або нові `jss_*`-ключі
(вирішиться на реалізації; нових рядків мінімум).

## Risks / Trade-offs

- **[Дублювання модалки]** → Окрема `JrSyncSettingsModal` дублює `Sheet`-каркас
  TimeCamp-модалки, але вміст інший (1 тогл vs тогл+select); абстрагувати зараз —
  передчасно. Приймаємо мінімальне дублювання.
- **[Семантика «синк» = `is_watched`]** → У Jira немає окремого `is_sync`;
  `is_watched` — єдиний прапор «чи стежимо за проектом». Лейбли фільтра/стану
  однакові з TimeCamp («у синку / не в синку») для консистентності.
- **[`issues_count` для всіх]** → Уже рахується без періоду; нічого не міняємо.

## Migration Plan

- **Frontend-онлі:** оновити `JrProjects.vue` + стор + нова модалка + i18n;
  `npm run build` (`vue-tsc` + `vite`) має бути чистим. Розгортання — звичайний
  фронт-білд; rollback — ревертом коду. Бекенд не зачіпається.
