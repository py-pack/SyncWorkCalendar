## ADDED Requirements

### Requirement: Повний синк задач Jira за відстежуваними проектами

Система SHALL надавати `POST /sync/jira/issues-all`, що тягне з Jira задачі
**відстежуваних** проектів (`jr_projects.is_watched = true`) і робить upsert у
`jr_issues`. На відміну від `POST /sync/jira/issues` (точково за ключами) і
побічного витягу через `POST /sync/jira/worklogs` (лише задачі з worklog-ами),
цей ендпоінт тягне задачі **незалежно** від наявності worklog-а та від
assignee/reporter (включно з «чужими»). Endpoint MUST вимагати валідний
Bearer-токен.

- **Опційний період активності:** тіло `{ start, end }` (date) обмежує вибірку
  задачами, **активними** (оновленими) у вікні — JQL-умова за полем `updated`
  (`updated >= start AND updated <= end`), незалежно від дати створення. Без тіла —
  усі задачі watched-проектів.
- Пошук виконується за JQL `project IN (<ключі watched-проектів>)` (+ умова
  `updated`, якщо задано період) з **пагінацією** (послідовні запити
  `startAt`/`maxResults`, доки вибрано всі задачі), тож результат не обмежується
  першою сторінкою.
- Запис — **upsert** (наявні задачі оновлюються, нові додаються); задачі поза
  вибіркою **не** видаляються.
- Виклик обгортається в `run_job` (запис у `api_jobs`, життєвий цикл
  `running → needs_verification | failed`), як інші sync-тригери.
- Підтримується `?background=true`: відкладене виконання → `202 Accepted` з
  `job_id`; синхронний виклик → `200 OK` з результатом (лічильник синкнутих задач).
- Якщо відстежуваних проектів немає — синк завершується успішно з нульовим
  результатом (нічого тягнути).

#### Scenario: Витяг задач watched-проектів за період активності

- **GIVEN** є відстежувані проекти (`is_watched = true`) із задачами в Jira, серед
  яких є задачі без worklog-ів і не заасайнені на поточного користувача
- **WHEN** авторизований клієнт викликає `POST /sync/jira/issues-all` з тілом
  `{ start, end }`
- **THEN** у `jr_issues` зʼявляються/оновлюються задачі цих проектів, **оновлені**
  (активні) у вказаному періоді (незалежно від дати створення), а відповідь містить
  лічильник синкнутих задач

#### Scenario: Пагінація — вибираються всі задачі, не лише перша сторінка

- **GIVEN** відстежуваний проект має більше задач, ніж розмір сторінки Jira-пошуку
- **WHEN** клієнт викликає `POST /sync/jira/issues-all`
- **THEN** синк проходить усі сторінки (`startAt`/`maxResults`) і зберігає задачі з
  усіх сторінок, а не лише з першої

#### Scenario: Фоновий режим

- **WHEN** клієнт викликає `POST /sync/jira/issues-all?background=true`
- **THEN** відповідь `202 Accepted` із `job_id`, а статус відстежується через
  `GET /api-jobs/{id}`

#### Scenario: Немає відстежуваних проектів

- **GIVEN** жоден проект не має `is_watched = true`
- **WHEN** клієнт викликає `POST /sync/jira/issues-all`
- **THEN** синк завершується успішно з нульовим результатом (жодних задач не
  витягнуто)

#### Scenario: Без токена

- **WHEN** клієнт викликає `POST /sync/jira/issues-all` без `Authorization`
- **THEN** відповідь `401 Unauthorized`
