## Why

Екран `/timecamp` зараз показує **лише незіставлені записи** (`GET /tc-entries/untracked`):
серверний фільтр жорстко відкидає всі записи, у яких є `meta.task` або змаплений
проект, тож щойно запис зіставлено із задачею — він зникає з екрана («не бачу
задач»). Період перегляду захардкоджено (останні 6 місяців), пагінації немає, а
синхронізація відбувається автоматично у фоні при кожному відкритті — що
користувач визнав некоректним (зайве навантаження на зовнішнє API + шум
`api_jobs`). Потрібен повноцінний екран записів TimeCamp із вибором періоду,
пагінацією, фільтром стану синку та **явною** кнопкою синку.

## What Changes

- **BREAKING (поведінка екрана):** `/timecamp` більше **не** робить авто-синк при
  відкритті. Екран читає **лише з локальної БД**; синхронізація з TimeCamp —
  тільки через явну кнопку. Авто-синк (`autoSyncEntries` на `onMounted`)
  прибирається.
- **Новий read-ендпоінт `GET /tc-entries`** — усі записи TimeCamp за період із:
  - параметром періоду `start`/`end` (дефолт — поточний місяць);
  - фільтром стану синку `synced=all|synced|unsynced`;
  - пагінацією `limit`/`offset`, відповідь `{ items, total }` (прецедент
    `GET /api-jobs`).
  - Кожен запис віддає `is_synced` (бінарно): `true`, якщо для нього існує
    `worklog_sync_task` у статусі `created`/`updated` для `worker_key` поточного
    користувача (worklog уже в Tempo).
- **Наявний `GET /tc-entries/untracked` залишається** без змін (знадобиться для
  майбутньої фічі ручного зіставлення).
- **Переписаний екран `/timecamp`**: вибір періоду перегляду, фільтр-чипи
  `усі | синхронізовані | не синхронізовані`, пагінація під таблицею, кнопка
  синку у правому верхньому куті.
- **Попап синку** з вибором періоду та **швидкими шаблонами** (останній тиждень,
  останній місяць тощо), що викликає наявний `POST /sync/timecamp/entries`.

### Modified Capabilities

- `api-sync-status`: додається нова вимога «Перелік записів TimeCamp із станом
  синку та пагінацією» (`GET /tc-entries`); наявна вимога про
  `GET /tc-entries/untracked` зберігається без змін.
- `frontend-data-tables`: вимога «Екран TimeCamp» переписується — замість показу
  лише незіставлених записів + авто-синк, екран читає всі записи з локальної БД
  за обраним періодом із пагінацією, фільтром стану синку та явною кнопкою синку
  з попапом (період + шаблони). Авто-синк прибрано.

## Impact

- **Backend (`api/`):** новий handler `GET /tc-entries` (роутер
  `app/api/routers/sync_status.py` або новий `tc_entries.py`); нова схема
  відповіді (`TCEntryItem` + сторінкована обгортка) у `app/api/schemas/`; DAO-метод
  у `app/dao/tc_entries_dao.py` (LEFT JOIN `worklog_sync_tasks` за `source_id` +
  `worker_key`, фільтр стану, `limit`/`offset`, `total`). **Без alembic-міграції**
  (усі колонки вже існують; head `10b7dc50b00f`).
- **Frontend (`front/`):** `views/TimeCampView.vue` (переписаний), новий попап
  синку (`components/...`, патерн `Sheet` як у `SyncSettingsModal.vue`),
  `api/client.ts` (метод `tcEntries`), `api/types.ts` (типи), `stores/tables.ts`
  (`loadTcEntries` зі станом period/filter/page; прибрано `autoSyncEntries` з
  екрана; синк через попап), `lib/period.ts` (хелпери шаблонів періодів), i18n
  (UK/EN).
- **Out of scope:** ручне зіставлення untracked-записів із задачами; перенесення
  цього ж патерну (read-from-DB + явний синк) на `/jira` і `/tempo` —
  **наступні окремі зміни** за тим самим принципом (зафіксовано в Memory Bank).
  Синк за розкладом — майбутній етап roadmap.
